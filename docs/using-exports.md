# Using the exports in apps

Everything under `tokens/exports/` is generated by `bkr export --all`. Apps
should read these files and never copy hex values by hand.

Pull the kit into an app however suits it: a Git submodule, a copy step in CI,
or (for public kits) a `bkr publish` bundle.

## Plain CSS

```html
<link rel="stylesheet" href="brand/tokens/exports/css/variables.css">
```

```css
body {
  background: var(--acmelabs-palette-surface);
  color: var(--acmelabs-palette-body);
  font-family: var(--acmelabs-font-family-body);
}
.button {
  background: var(--acmelabs-palette-primary);
  color: var(--acmelabs-palette-on-primary);
  border-radius: var(--acmelabs-radius-md);
}
```

Dark mode is automatic when the kit has `tokens/themes/dark.bkr.json`: it
follows the visitor's system setting. Force a theme with
`<html data-theme="dark">` or `<html data-theme="light">`.

## Tailwind v4

```css
@import "tailwindcss";
@import "./brand/tokens/exports/css/variables.css";
@import "./brand/tokens/exports/tailwind/theme.css";
```

Then use classes like `bg-palette-primary`, `text-palette-on-primary`,
`font-heading`, `text-heading`, `rounded-md`. Because the theme points at the
CSS variables, dark mode switches automatically.

## Tailwind v3

```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: require("./brand/tokens/exports/tailwind/theme.cjs"),
  },
};
```

v3 values are raw hex, so opacity modifiers (`bg-palette-primary/50`) work, but
the dark theme does not apply automatically; use the CSS variables for that.

## DTCG (Style Dictionary, Figma plugins, other tools)

`tokens/exports/dtcg/*.tokens.json` follows the W3C Design Tokens format
(2025.10). Colors look like:

```json
{ "$type": "color", "$value": { "colorSpace": "srgb", "components": [0.1451, 0.3882, 0.9216], "hex": "#2563eb" } }
```

Theme overrides are in `tokens/exports/dtcg/themes/`.

## AI assistants

Give agents `AGENTS.md` first. For UI work, also give
`tokens/exports/agent/ui-brief.md`: it lists every token with its CSS variable,
use, and the approved text and background pairs.

## Keeping apps in sync

- Run the [GitHub Action](../README.md#github-action) in the kit repo so exports are always current.
- In the app repo, update the submodule or copied files when the kit changes.
- Breaking changes (renamed variables) are listed in `CHANGELOG.md` and `spec/MIGRATION.md`.
